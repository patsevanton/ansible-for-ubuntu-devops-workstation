# TODO: полезные утилиты, которые ставятся через npm

Плейбук ставит Node.js и npm (роль `runtimes`) и уже использует `npm install
-g` для `inshellisense`, `tldr`, `kubebox`, `kosko`, `cdk8s` и `@apify/mcpc`.
Но новые кандидаты, у которых единственный путь установки — npm-пакет, пока
сознательно не добавляются: глобальные npm-пакеты дублируют `package.json` в
домашнем каталоге, требуют `sudo` на `/usr/local` и обновляются отдельно от
остальных ролей (`sudo npm update -g`).

Записано 2026-11-21. Как читать: `- [ ]` — не добавлен; в заметке — что
именно проверить перед добавлением.

## Кандидаты

- [ ] **markdownlint-cli2** — [DavidAnson/markdownlint-cli2](https://github.com/DavidAnson/markdownlint-cli2).
      Линтер Markdown: заголовки, списки, code fence, длина строк, битые
      ссылки внутри документа. В этом репозитории README ~3,2 тыс. строк и
      десятки правил оформления, а `pre-commit` и CI проверяют только YAML
      (`yamllint`) и Ansible (`ansible-lint`); Markdown не проверяется ничем.
      Пакет на npm: `markdownlint-cli2`, команда `markdownlint-cli2`.
      Проверить перед добавлением:
      - конфиг `.markdownlint-cli2.yaml` и набор правил, которые не ломают
        существующий README (например, `MD013` про длину строк и `MD033`
        про inline HTML обычно отключают);
      - запуск в `pre-commit` и в `.github/workflows/lint.yml`;
      - обновление: пакет попадает под общий `sudo npm update -g`, отдельная
        задача роли не нужна.

## Почему не ставим сейчас

Решение от 2026-11-21: npm-пакеты в плейбук пока не добавляются. Если
markdownlint понадобится, удобнее сначала прогнать его вручную
(`npx markdownlint-cli2 "**/*.md"`) и посмотреть, сколько замечаний он даёт на
текущем README, а уже потом решать про роль и CI.
